Deploy the live demo

The serving image is built on every main branch CI run, gated, and published to GHCR. The live service is self-contained (certified model baked in) so it needs no database.

  1. Open render.yaml in the repository root and click New → Blueprint on render.com, selecting this repo.
  2. Render builds docker/serving.Dockerfile and starts modelops-serving on the free plan.
  3. /predict, /metrics, /model/info, and the live /demo dashboard are reachable at your *.onrender.com URL.

Full production stack (local / self-host)

PostgreSQL backend store + MinIO (S3-compatible) artifact store + MLflow server. Swap MinIO for real AWS S3 via two env vars.

eval "$(./scripts/devstack.sh env)"
python -m src.pipeline --track        # validate -> train -> track -> gate
uvicorn src.serving.api:app --port 8000
python -m src.monitoring              # PSI drift check + retrain alert
docker compose up                     # postgres, minio, mlflow, serving,
                                      # prometheus, grafana (+ airflow profile)

Guarantees (coding-agent operating rules)

  • ✓ One module fully working before the next — committed after every feature
  • ✓ Every metric measured, never estimated (benchmark file checked in)
  • ✓ Regression gate blocks deploys — FAIL run leaves production untouched
  • ✓ Tests: 38 passing (gate PASS + FAIL, registry, drift, serving, validator)
  • ✓ Config-driven thresholds + seeds; data hashes for lineage
  • ✓ Drift alerts → scheduled retraining trigger (GitHub cron)
